# M2 품질 계약 및 sandbox 실행 계약 자체 리뷰

범위: #14, #52. 최신 main `be1e6e1` 기반.

## 확인하고 수정한 결함

1. 기존 API/TUI/watch는 마지막 probe 성공 여부를 0/100% 손실로 표시했고 Prometheus는
   SQLite 1분 집계를 사용했다. 프로세스 내 단일 window 집계와 immutable snapshot을
   공유한다. 저장 실패는 별도 상태이며 현재 측정을 왜곡하지 않는다.
2. discovery 실패는 아무 결과도 발행하지 않아 이전 good이 남았고, 제거된 peer의
   Prometheus gauge도 남았다. 실패 snapshot을 즉시 발행하고 수집 중단 시 read/scrape
   시점의 freshness로 unknown 처리한다. 정상 discovery의 제거는 gauge에서도 제거한다.
3. 신규 구현의 clock 역행 검사에서 읽기 잠금 전에 시각을 취하면 잠금 획득 중 새로
   발행된 snapshot을 미래 시각으로 오판할 수 있었다. 동시 HTTP/scrape 회귀 100회
   실행에서 수정 전 실패를 재현했다. snapshot을 확보한 뒤 현재 시각을 취하도록 수정하고
   같은 race 검사 100회가 통과했다. 실제 clock 역행의 unknown/window 초기화도 유지했다.
4. 잘못된 IP/port는 network probe를 하지 않았는데 실패 이력에 저장될 수 있었다.
   이를 unknown/표본 0/null 수치로 표현하고 history와 probe counter에 넣지 않는다.
5. UDP deadline과 취소 callback의 socket close가 경합하면 timeout이 일반 오류로
   보일 수 있었다. probe context의 deadline 원인을 우선 반영한다. 실제 무응답 UDP와
   진행 중 probe 취소를 검사했고 종료를 network loss로 기록하지 않는다.
6. sandbox의 공유 Docker tag가 병렬 실행 중 교체될 수 있었다. 각 빌드에서 기록한
   image ID로 실행하고 실제 제품/suite digest 및 실행 조건을 manifest에 보관한다.

## 검증과 판단 범위

- 전체 `go test -race -count=1 ./...`, normal/integration vet, build 통과.
- monitor race 20회(1 CPU), 동시 publication/HTTP/scrape 회귀 100회 통과.
  마지막 review 수정 뒤 monitor 전체 race도 통과했다.
- HTTP/metrics/TUI/watch 20% 손실·성공 RTT 평균 일치, window와 stale 경계, 표본 부족,
  회복 히스테리시스, snapshot pointer 격리, 설정 검증, 저장 오류, peer 제거/재등장 확인.
- 외부 바이너리(공백 포함 경로)를 이용한 실제 WG monitor CLI/HTTP/metrics 검증 통과.
  응답기 중단/복구, interface 제거, 빈 peer 집합 및 프로세스 정상 종료를 확인했다.
- 전체 kernel 회귀와 PR/병합 main CI의 최종 결과는 PR 및 #14/#52에 기록한다.

확인한 리뷰 결함은 조치했다. 위 단위·실제 CLI 계약 범위에서 새 차단 결함은 확인하지
못했다. 병합은 필수 CI 성공을 조건으로 한다.

## 호환성과 잔여 범위

`/network/quality`는 schema version 1 object로 변경된다. 이전 배열 소비자는 `peers`로
이전해야 한다. Prometheus quality에는 -1 unknown이 추가되며 누락 수치는 NaN이다.

최근 품질은 새 프로세스의 표본만 사용한다. `fleet` 및 중앙 history 통일은 #15,
독립 probe에 따른 tunnel/underlay/server 원인 식별은 #16이다. timeout만으로 원인을
단정하지 않는다. M2 전체나 M3 다중 relay/통신망 전환 완료로 확대하지 않는다.

배포 설정 문서는 다른 저장소가 가져다 쓸 계약이다. 실제 운영 호스트에는 적용하지
않았다. sandbox도 외부 바이너리를 받을 수 있지만 suite checkout/Go toolchain을
포함한 독립 배포 패키지까지 제공하는 단계는 아니다.
