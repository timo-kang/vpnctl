# 동시 이력 업로드 연결 수명 자체 리뷰

## 결함 및 근거

PR #81의 사전 CI는 통과했지만 main `6273f9c`의 실행 `36372599658`에서 schema 6/7의 32노드 생산자가 45초 내 수렴하지 못했다. 따라서 이전 생산자 완료 보고의 반복 안정성 판정은 수정한다. 추적: #82.

대부분 노드에 일부 관계만 저장되었고 큐 누락이 증가했다. 2 CPU race CPU 프로파일은 Store.Ingest 약 46%, 연결 생성 약 19%, 테스트 Latest 폴링 약 2%였다. 단일 관측마다 연결을 새로 열면서 SQLite 설정·스키마 파싱 및 마지막 연결 종료 비용을 반복했다. CI job 분리만으로 해결되지 않았다.

## 수정과 수명 불변 조건

Ingest의 입력 검증 뒤, writer 대기 전에 참조를 획득한다. 동시에 진행 중인 Ingest만 하나의 `sql.DB`와 최대 한 개의 연결을 공유한다. 기존 writer admission은 유지하며 거래는 직렬화한다. 마지막 참조를 반환할 때 DB를 닫는다. 외부 Close 호출, idle 타이머, 영구 연결을 도입하지 않는다.

- 대기 중 취소된 요청도 참조를 반환한다. 다른 요청의 연결은 닫지 않는다.
- 거래 rollback/commit 뒤 writer를 해제한 다음 연결 참조를 반환한다.
- 마지막 close와 다음 pin은 같은 mutex로 직렬화한다.
- 공유 구간 종료 후 새 요청은 새 연결을 연다. 실패한 거래를 재사용하지 않는다.
- synchronous FULL, WAL 예산, foreign keys, DB 공간 예산, quota, 멱등성 및 인증·삭제 장벽은 유지한다.
- 다른 종류의 이력 작업은 기존 연결을 사용한다. 서버 상태와 연결 수명의 새 종료 순서 의존성을 만들지 않는다.

## 검증 범위

`TestConcurrentUploadsCancelAndReleaseConnection`은 schema 5/6/7에서 64개 대기 중 절반 취소, 나머지 커밋, FULL/foreign keys, 마지막 연결 폐쇄, 재시작한 정확한 표본 수, 새 쓰기와 충돌 후 복구를 검증한다.

같은 2 CPU 조건의 실제 32노드 race 시험에서 기존 schema 7은 30.32초, 수정 후 schema 6/7은 17.33/18.29초였다. 1초 cadence, 45초 제한, source당 992개 관계 판정은 바꾸지 않았다. 호스트별 성능 수치를 운영 SLO로 해석하지 않는다.

전체 schema 5/6/7 × 1/3/8/32노드 반복, 저장/컨트롤러 race 및 CI의 최종 결과는 연결된 PR에 기록한다. schema 5의 32노드는 quota 검증이며 전체 수용 판정이 아니다.

## 잔여 범위

1초 전노드 full mesh 생산의 장기 무손실 수용을 인증하지 않는다. 큐는 여전히 bounded best-effort이다. 종료 시 미전송 누락을 포함한 표시도 유지한다. 운영 cadence별 지속 처리량과 24시간 복합 soak는 #71/#19의 후속 gate이다. 인증서 갱신·다중 릴레이 경로 제어의 완료 판정을 대체하지 않는다.
