## 인정하지 않는 범위와 남은 조건

분석기의 population 판정은 `not_reconcilable_from_soak_trace`다. window 조회와 counter
증분은 전체 입수 원장이 아니며 관측되지 않은 재시작·초기 구간을 포함하지 못한다.
truncation 0만으로 전체 생산량 보존을 주장하지 않는다. 자원 peak도 연속 최대가 아닌
표본값이고 read latency를 heartbeat·인증 갱신·경로 제어 지연으로 대체하지 않는다.

이번 baseline에는 지속적인 pinned WAL/quota 압력이 없다. #19 최종 판정에는 같은 장기
실행의 저장 압력·생산/보존/회수/expiry/drop 대조·제어 요청 지연, 실제 배포 자원/예산,
API/CLI/화면의 동일 표본 대조가 남는다. 별도 #101 CA ACK 지연, #102 fuzz 종료,
#115 baseline 인증 갱신/ACK 2초 초과의 미해결 원인을 이 성공으로 닫지 않는다.
이번 증거는 #107/#110 수정이 포함된 소스의 장기 복합 회귀 통과이며 M3 변경의 검증은 아니다.

후속 PR #120의 단기 production CI에서는 underlay 복구 뒤 한 peer의 관측 누락으로
실패한 별도 실행이 나왔다. [#121](https://github.com/timo-kang/vpnctl/issues/121)에 원본과
확인한 재측정 지연, 추가 원인 규명 조건을 기록했다. 이 후속 실패도 보존하며 이 문서의
성공한 24시간 실행과 혼합하거나 덮어쓰지 않는다.

다음 실행이 필요할 때도 이 결과를 덮어쓰거나 다시 시작하지 않고 별도 run으로 남긴다.
