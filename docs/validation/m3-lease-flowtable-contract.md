# Lease 전역 flowtable 검사 계약

이 변경은 실제 커널을 이용한 안전 회귀를 추가한다. 제품의 독립 전역
flowtable 조회와 소유 lease 테이블 조회, 승인·만료 및 준비/활성화 처리는
유지한다. #185의 용량·관측 지연 판정은 별도이며 이 시험으로 완료되지 않는다.

## 독립 조회가 필요한 이유

전역 flowtable은 소유 lease 테이블 밖에도 존재할 수 있다. 테이블에 한정된
조회 결과를 전역 부재의 증거로 사용하면 lease 차단을 우회하는 경로를 놓칠
수 있다. 격리된 nft 1.0.6 환경에서 전역 조회와 특정 테이블 조회를 한 명령
묶음으로 실행하면 외부 flowtable이 누락되는 반례를 확인했다. 따라서 각
검증 경계에서 전역 조회를 독립적으로 수행한다. 이 반례를 모든 nft 버전의
동작으로 일반화하지 않으며, 회귀는 특정 upstream 오류의 재현을 요구하지 않는다.

## 실제 커널 회귀

`TestLiveLeaseReadGlobalFlowtables`는 production `LeaseStatus`와 `Lease`에
대해 다음 계약을 확인한다.

1. 소유 lease를 만들고 일반 외부 테이블만 있을 때 정상 조회한다.
2. 외부 `inet`, `ip`, `ip6` flowtable이 생기면 상태 조회와 새 승인에 따른 갱신을 거부한다.
3. 삭제하면 정상 조회하고, 다시 추가하면 다시 거부한다. 이전 결과를 재사용하지 않는다.
4. 모든 조회 후 빈 fixture lease가 자동으로 활성화되지 않았는지 확인한다.

`scripts/test-route-query.sh`와 CI의 커널 계약 검사에서 기존 route 검증과
함께 실행한다. 새 network-none 컨테이너에 CAP_NET_ADMIN만 부여하고 CPU,
메모리, PID 및 실행 시간을 제한한다. fixture는 Docker, 초기 loopback-only
namespace와 정확한 capability를 확인해 호스트 실행을 거부한다.
주소·키·원시 nft 출력 대신 고정 결과와 버전만 기록한다.

정상 코드의 계약은 통과했고, 상태 조회 또는 staged 갱신에서 독립 전역 검사를
잘못 결합한 두 변이는 세 주소군의 거부 assertion에서 검출됐다. 과거 CI의
용량 실패는 그대로 보존하며, 이 보강을 성능 향상이나 M3 완료 근거로 사용하지 않는다.
미채택 성능 실험의 원본·계측 결과는 별도 비공개 기록으로 관리한다.
